SM ENGINE — ARCHITECTURE / PROCEDURAL BUILDING SYSTEM v1
=========================================================

TARGET
------
Turn a deterministic architectural map into a complete editable Three.js
building hierarchy.

Recommended native map extension:

    *.smbuilding.json

Compact alias supported by the AssetsPanel bridge:

CORE IDEA
---------
Image/PDF/plan is NOT the runtime contract.

The deterministic contract is:

    plan / BIM / AI
        -> SM_BUILDING_MAP
        -> SMBuildingSchema
        -> SMBuildingGraph
        -> SMBuildingGenerator
        -> Three.js Object3D hierarchy

This makes generation reproducible and debuggable.


OPENINGS WITHOUT CSG
--------------------
v1 intentionally does NOT depend on three-bvh-csg.

Doors and windows are generated by splitting each wall into valid solid
rectangles around the openings. This avoids the current CSG/load-order problems
in the project and is faster for ordinary architectural walls.


QUICK START
-----------
After the loader order is installed:

    const mapText = await fetch(
        'engine/architecture/examples/palace-demo.smbuilding.json'
    ).then(r => r.text());

    const building = SMArchitecture.generate(mapText);
    scene.add(building);

or:

    const map = SMArchitecture.parse(myJsonObject);
    const building = smBuildingGenerator.generate(map);
    window.addObjectToScene?.(building, building.name);


ASSETSPANEL
-----------
If SMArchitectureAssetsBridge loads after AssetsPanel:

    .smbuilding.json
    .smap

are registered as type:

    building-map

Dropping the building-map asset into the viewport generates a real Three.js
building object.


MAP COORDINATES
---------------
2D plan coordinates are:

    [x, z]

Vertical coordinate is generated as Three.js Y.

All normalized runtime units become meters.


WALL OPENINGS
-------------
Opening offset is measured from the wall START point to the CENTER of the
opening.

Example:

    wall from [0,0] to [10,0]
    door offset 5
    width 1

means the door occupies approximately x=4.5..5.5 along that wall.


SVG CONTRACT
------------
Prefer semantic attributes:

    <line
        id="wall_south"
        data-sm-type="wall"
        x1="0" y1="0"
        x2="1800" y2="0"
        data-sm-height="4.2"
        data-sm-thickness="0.28" />

    <polygon
        id="hall"
        data-sm-type="room"
        points="600,0 1200,0 1200,800 600,800" />

    <rect
        id="main_door"
        data-sm-type="door"
        data-sm-wall="wall_south"
        data-sm-offset="900"
        data-sm-width="240"
        data-sm-height="320" />

Default SVG scale is:

    0.01

so SVG centimeters become meters.


DXF v1
------
The included DXF importer intentionally starts conservative:

- ASCII DXF
- LINE entities
- semantic layer containing WALL

This avoids silently inventing geometry.

Later versions can add:
- LWPOLYLINE rooms
- INSERT blocks for doors/windows
- ARC/CIRCLE columns
- layer mapping profiles


AI / VISION
-----------
SMPlanVisionBridge is provider-agnostic.

You configure an analyzer:

    smPlanVisionBridge.setAnalyzer(async (imageOrPayload, contract) => {
        // call your AI service here
        // return SM building-map compatible object
    });

Then:

    const result = await smPlanVisionBridge.convert(image);

The bridge validates the result before the procedural generator receives it.

Important rule:
AI should not generate final meshes directly.
AI should convert uncertain plans into the deterministic SM_BUILDING_MAP.


MATERIALS
---------
Map materials can contain simple PBR definitions:

    "materials": {
        "wall": {
            "color": 15198183,
            "roughness": 0.72,
            "metalness": 0
        }
    }

If SMMaterialLibrary contains a matching material name, the resolver can reuse it.
Otherwise SM Architecture creates and caches its own MeshStandardMaterial.

KNOWN v1 LIMITS
---------------
- hip roof currently falls back to a structural flat slab and records the
  requested type in userData.
- curved walls are not yet represented.
- arbitrary stair types (L/U/spiral) are not yet generated.
- advanced BIM entities and IFC import are not in v1.
- DXF importer does not infer doors/windows from arbitrary CAD conventions.
