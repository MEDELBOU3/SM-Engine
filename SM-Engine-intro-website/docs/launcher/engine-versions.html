Engine Versions

Install, switch, and maintain multiple SM Engine builds. The launcher keeps one active version and tracks the rest via EngineVersionManager and UpdateService.

List installed versions

The Engine Versions view calls engine:listVersions → EngineVersionManager.listAllVersions(). Each entry shows version, channel, path, and whether it is the current active build. The sidebar and top bar update automatically when the list changes.

Install a new version

Click Install on a release card. The renderer sends engine:installVersion with version and download URL. The main process delegates to UpdateService.installVersion(version, url, onProgress), which streams the download and forwards progress events (engine:downloadProgress) to the UI. On success, the launcher fires engine:installed and logs an analytics event.

IPC Main Handler UI Effect
engine:installVersion UpdateService.installVersion Shows progress, then refreshes the version list.
engine:cancelDownload UpdateService.cancelDownload Stops the in-progress download.
engine:uninstallVersion UpdateService.uninstallVersion Removes the build from disk and the list.

Set the active version

Click Set as Active on any installed build. This sends engine:setActive → EngineVersionManager.setActiveVersion(path), which updates the stored setting and the version shown in the top bar. New projects use the active version by default.

Add a custom engine

Choose Add Custom Engine and select a folder. The launcher runs engine:addCustom → EngineVersionManager._inspectEngineDirectory(path, true, 'Custom') to validate the directory, then marks it as active. This is useful for local development builds via SM_ENGINE_DEV_PATH.

Tip The launcher also exposes engine:addCustom via a folder picker — the same flow used for Add Existing Project, but for engine directories.
