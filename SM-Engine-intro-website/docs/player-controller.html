Player Controller

The player system (SMPlayerSystem) is a full character controller: first/third-person input, physics-driven movement, ground snapping, procedural camera and animation blending — exposed globally as window.player.

Where the player exists — the character is only enabled in the Game Development and Gameplay Sample workspaces. In FILM or TERRAIN workspaces it is hidden, disabled and skipped in physics until you switch back (Gameplay & Sample Mode).

Architecture

engine\player\SMPlayerSystem.js composes a set of sub-systems, each in its own folder:

ModulePathResponsibility
PlayerCharactercore\PlayerCharacter.jsGLTF model, visual hierarchy, height, visibility
PlayerStatecore\PlayerState.jsspeed, velocity, movement state + reset
PlayerInputControllerinput\PlayerInputController.jskeyboard/mouse input, setEnabled()
PlayerMovementControllermovement\PlayerMovementController.jsvelocity integration, acceleration
PlayerGroundingmovement\PlayerGrounding.jsfloor detection, snap to ground
PlayerRotationControllermovement\PlayerRotationController.jscharacter facing direction
PlayerCameraControllercamera\PlayerCameraController.jsfirst/third-person camera follow + activate()/deactivate()
PlayerAnimationControlleranimation\PlayerAnimationController.jsanimation actions map, currentKey
PlayerAnimationStateMachineanimation\PlayerAnimationStateMachine.jsidle/walk/run/jump transitions

Core API

window.player;            // SMPlayerSystem instance (alias window.playerSystem)
player.ready;             // true after GLTF load + systems constructed
player.enabled;           // active in the current workspace
player.character.model;   // the GLTF character (null until loaded)
player.character.height;  // character height for camera/collision
player.animation.actions; // Map of animation clip names
player.animation.currentKey;

player.activate();        // enable input, movement, animation, physics
player.deactivate();      // disable everything and hide

player.update(delta);     // called every frame by the engine
player.setWorkspaceMode("GAME_DEV"); // workspace gating

player.on("ready", ({ workspace, model }) => { ... }); // event emitter

Player Mode & Camera

Player Mode switches the editor camera to a third-person follow camera and hands control to the character. It is toggled from the Player panel in the Game Development / Gameplay Sample workspaces. 

window.setPlayerControlMode(true);   // enter player control (WASD + mouse)
window.toggleControlMode();           // flip current state
window.isPlayerControlActive;         // boolean state

// Behind the scenes: a ThirdPersonCamera is created on demand
window.tpsCamera = new ThirdPersonCamera(window.camera, player.model);
window.controls.enabled = !desiredState; // orbit controls released when driving

Loading Player Models

The engine ships with a built-in model library (PLAYER_MODEL_LIBRARY, exposed as window.availablePlayerModels) for the model dropdown in the Player panel. Loading a model re-initializes the character, rebinds the rig, and if player mode was active it automatically re-activates. 

window.loadPlayerModelByPath("models/player/cartoon-robot.glb");
window.loadPlayerModelFromFile(file); // from a local file input

player.init(gltf, window.collidableMeshes || [], window.obstaclesGroup, window.ground);

Integrated Systems

  • Player Graph Editor — visual node graph for player logic (window.playerGraphEditor), paused automatically when leaving player mode.
  • GPS Mini-Map — window.gpsMiniMap top-down minimap with spawn/platform points of interest.
  • UAL2 Runtime — window.ual2Engine player integration for runtime logic.
  • Rig System — rigManager.setupRigForObject() binds animation rigs to the loaded character.

Scripting Example

// In the Gameplay Sample workspace:
window.workspaceManager.applyMode('GAMEPLAY_SAMPLE');

player.on('ready', () => {
    console.log('Player ready with', player.animation.actions.size, 'animations');
    player.activate();          // character appears
    window.setPlayerControlMode(true); // take control
});
