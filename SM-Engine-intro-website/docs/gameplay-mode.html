Gameplay & Sample Mode

SM Engine ships with dedicated gameplay environments for testing movement, jumping, physics and your character controller — a UE-style purple playground plus a full game-development sky world. These are workspaces: switching between them reconfigures the whole viewport (sky, fog, floor, obstacles, player, grid and lighting profile) in one click.

Switching Workspaces

Workspaces are switched from the workspace mode modal: click the current mode tag (top-left, e.g. FILM) in the viewport header to open the card grid, then pick a card. The choice is persisted in localStorage.sm_workspace_mode and restored on reload. There are no workspace F-key shortcuts — the F-keys are reserved for the game mode manager (see Game Mode Manager).

Gameplay Sample Environment

The Gameplay Sample workspace loads the UE-style purple playground (SMGameplaySampleEnvironment + SMGameplaySampleCourse): a large ground plane, color-coded obstacle courses, ramps, platforms and moving elements built for character testing.

  • Fog — soft purple, 38 to 285 units, blending distant course elements.
  • Background — solid #8177ad, exposure 0.92.
  • Physics — the environment registers every collidable mesh with the physics system automatically (environment.registerPhysics(physicsSystem)), so the player collides with ground, walls and obstacles out of the box.
  • Obstacles — a dedicated obstaclesGroup for hazards and moving blocks.

Game Development Environment

The Game Development workspace is the full sky world: dynamic sky + HDRI, fog, floor and obstacle set, with the player character enabled and physics active. This is the intended home for real gameplay scenes — build your level here, then use the player controller to walk through it.

Game Mode Manager & F-Keys

The GameModeManager (js/GameModeManager.js) drives viewport overlays and flags per game mode. Its MODE_* profiles control things like grid visibility and safe frames; each mode maps onto a workspace configuration, and grid.visible is synced from the active profile:

  • F1 / F2 — editing / preview game modes.
  • F3 — MODE_TERRAIN: terrain-first mode with grid on and terrain cursor (sm-terrain-cursor) active.
  • MODE_CINEMATIC — safe-frame overlays for framing shots.

Scripting Reference

// Switch workspace programmatically
window.workspaceManager.applyMode('GAMEPLAY_SAMPLE'); // or FILM / GAME_DEV / TERRAIN

// Environment hooks
window.environment.registerPhysics(window.physicsSystem); // collidable meshes → physics

// Game mode manager
window.gameModeManager?.setMode('TERRAIN'); // triggers grid + terrain cursor profile
Player visibility — the player character only exists in GAME_DEV and GAMEPLAY_SAMPLE. In other workspaces it is fully hidden and disabled until you switch back. See the Player Controller page for the full API.
