Workspaces & Modes

SM Engine is a mode-based editor. Each workspace (FILM, GAME_DEV, GAMEPLAY_SAMPLE, TERRAIN) reconfigures the scene, lighting, and environment, and the Game Dev workspace further switches between 2D, 2.5D and 3D play viewports.

Workspace Manager

The WorkspaceManager (js/app/WorkspaceManager.js) owns the mode registry, the workspace switching modal, per-mode scene presets and recent project list. Each mode stores a settings block that describes which environment layers are active:

  • sky — enables the atmospheric sky / HDRI dome.
  • fog — toggles scene fog for depth and atmosphere.
  • floor — the unreal-style ground plane (UnrealEngineFloor).
  • obstacles — the ObstaclesGroup of gameplay blockers.
  • player / horse — loads the playable character and horse controllers.
  • grid — Blender-style ground grid.
  • studioLights — neutral editor lighting rig.
  • lightingProfile — which environment rig the sky/lighting system binds (FILM_STUDIO, GAME_DEV_SKY, GAMEPLAY_SAMPLE, TERRAIN_LANDSCAPE).
Mode Key Purpose Default Scene Layers
Film / Studio FILM Clean studio viewport for modeling, sculpting, 2D animation and rendering. Studio lights, grid helper, HDRI on #1c1c1c, no fog/floor/player.
Game Development GAME_DEV UE-style gameplay iteration with player, horse, controls, collisions. Sky atmosphere + haze, floor + obstacles, player/horse controllers, gameplay lighting.
Gameplay Sample GAMEPLAY_SAMPLE Purple UE-style playground for movement, jumping, physics and character testing. Solid #8177ad background, purple fog (38–285), floor + obstacles, player, sample lighting rig.
Terrain TERRAIN Landscape focused workspace with terrain generation/vegetation. Terrain sky rig, terrain nodes, vegetation painter, water system, no floor/player.
Switching workspaces Click the current mode tag in the viewport header to open the workspace card grid (.ws-mode-card) and pick a mode. The active workspace is persisted in localStorage.sm_workspace_mode so the editor reopens with your last setup. There are no workspace F-key shortcuts — the F-keys drive the game mode manager instead (F3 = terrain mode). See Gameplay & Sample Mode for the full mode matrix.

Game Viewport Modes (2D / 2.5D / 3D)

Within the GAME_DEV workspace, GameModeManager (js/GameModeManager.js) switches the play viewport:

  • 2D (MODE_2D) — orthographic camera (top-down), arcade-style physics, background & grid visible.
  • 2.5D (MODE_2_5D) — perspective camera with a wider FOV for pseudo-3D platforming.
  • 3D (MODE_3D) — full perspective gameplay, advanced lighting, HDRI background, and hidden edit-mode grid.
  • Terrain (MODE_TERRAIN, F3) — terrain-first viewport with grid visible and the terrain sculpt cursor enabled.

The F-keys are handled by GameModeManager rather than the workspace system: game modes use profiles with flags such as gridVisible and cinematic safe frames (MODE_CINEMATIC), and the grid helper follows the active profile (grid.visible = vp.gridVisible).

Preset persistence The active workspace is stored in localStorage.sm_workspace_mode and the play view mode in sm_game_dev_mode, so the editor reopens with your last setup.

Startup & Welcome Modal

On first launch the editor shows the WorkspaceManager startup modal with recent projects, a Create box (new FILM or GAME_DEV project) and game-view submode buttons. Recent projects are kept in localStorage.sm_projects and can be loaded directly back into their workspace.
