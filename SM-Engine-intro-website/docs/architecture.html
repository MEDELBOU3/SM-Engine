Engine Architecture

Under the hood of SM Engine: how the editor boots, which libraries power its core, how render/simulation systems are wired, and where each source folder lives.

Runtime stack The editor runs on Three.js r147 (WebGL2), with physics from ammo.js / Bullet and cannon-es, UI dialogs via dat.GUI / lil-gui, node graphs via LiteGraph, and code editing through CodeMirror + Monaco. The desktop shell is Electron.

Application Bootstrap

The entry point is index.html. It loads roughly 120 local scripts in dependency order, ending with the engine core (engine/globals.js, engine/grid-materials-obstacles.js, engine/camera-system.js, engine/animate-loop.js, engine/SMViewportSystem.js) and finally the main orchestrator index.js. The whole scene is bootstrapped by a single guarded async function init() in index.js.

  1. Guard & error handling — initStarted/initCompleted flags keep init idempotent; a global window.__smInitErrorHandler captures startup errors.
  2. Scene — a THREE.Scene (background 0x393939) is created and exposed as window.scene, seeded with a hemisphere "editor" light.
  3. Camera — window.cameraSystem = new CameraSystem(scene, container, ...) builds the perspective camera (window.camera) and a top-down orthographic camera (window.orthographicCamera), then wires THREE.OrbitControls as window.controls (right-mouse disarmed).
  4. Renderer — a raw THREE.WebGLRenderer (antialias, logarithmicDepthBuffer, PCFSoft shadow maps, ACESFilmic tone mapping, exposure 0.55) is created and exposed as window.renderer.
  5. Viewport system — window.SMViewportSystem takes over #sm-viewport-root to host the multi-panel (tiling / game / mirror) viewport layout.
  6. Transform gizmo — THREE.TransformControls as window.transformControls, attached to the active camera and hardened for gizmo rendering.
  7. Engine subsystems — NaniteSystem (auto-LOD), PerformanceManager, WaterSystem, LumenLightingSystem, SkyLightingSystem (weather + atmosphere), terrain node editor, rig manager, UV inspector, history, sculpting, persistence and the game environment (floor + obstacles) are constructed in dependency order.
  8. Persistence — window.persistenceManager restores the last saved scene and starts a 60-second auto-save timer.
  9. Render loop — animate() is kicked via requestAnimationFrame.

Core Module Map

Module File Responsibility
renderer / scene index.js WebGL renderer, scene graph, guards, auto-save bridge (global window.renderer, window.scene).
CameraSystem engine/camera-system.js Perspective + orthographic cameras, orbit/perspective switching, camera-update events.
animate() engine/animate-loop.js The per-frame engine: physics tick, timeline playback, LOD, water/vegetation wind, viewport scissor rendering.
SMViewportSystem engine/SMViewportSystem.js Multi-panel tiling viewports, game-view panels, mirror splits, panel aspect/camera routing.
WorkspaceManager js/app/WorkspaceManager.js FILM / GAME_DEV / TERRAIN workspaces, per-mode scene presets, business modal.
SMTimeline js/timeline/sm-timeline-core.js Keyframes, playback, mixer sync, interpolation, binary evaluator.
PhysicsSystem physics/ui/PhysicsUI.js Ammo/Bullet rigid bodies, soft bodies, forces, joints, collision masks.
ScenePersistenceManager processing/persistence/ScenePersistenceManager.js Save/load scene JSON (IndexedDB), auto-save, project files.
HistoryManager history/history.js Unified undo/redo stack (default 50 steps) for transforms, timeline, materials.
PanelRegistry panels/PanelRegistry.js Boots modular panels: welcome, toolbar, hierarchy, inspector, modeling, timeline, asset, VFX, code, bone-rig.

Repository Folder Layout

  • engine/ — renderer & scene shell: camera-system, animate-loop, globals, grid-materials-obstacles (room floor/environment), advanced-lighting, SMViewportSystem, motion-matching player control.
  • js/app/ — WorkspaceManager, app-bootstrap (global bindings, panel resizers), editor-mode-save assistant.
  • js/timeline/ — sm-timeline-core, animation-converter, binary evaluator, timeline audio/events.
  • panels/ — all dockable panels and the welcome modal (Toolbar, Hierarchy, Inspector, Timeline, Sculpting, Asset, Code, BoneRig, VFX, Camera/lighting).
  • modeling/ + modifiers/ — mesh tools (knife, loop cut, bevel, bridges) plus the modifier stack (array, mirror, subdivision, bevel, solidify, decimate, lattice…).
  • sculpting/ — brushes, WASM sculpt engine (sculpt_engine.cpp), terrain sculpting, vegetation painting, hair system.
  • nodes/ — node editors: MaterialNodeEditor.js, NodeTerrainEditor.js, VFX studio, explosions.
  • physics/ — PhysicsSystem implementation living in physics/ui, zones, material brush.
  • rendering/ — SMRenderPipeline.js (post-processing passes, quality presets, offline/video render engine).
  • runtime/ — packaged game export loader (game-export-system.js, exported web template).
  • advanced-modeler/ — parametric/curve sketching: ProfileExtrusion, TwoDProfileDrawer, curve tangents, multiview canvas.
  • animations/ — character animation, bone controller, player graph, riggings, animation grid/camera tools.
  • 2D-editor/ — 2D canvas drawing, brush system, onion skin, storyboard, sprite editor, color/coloring system.
  • video-editing/ — tabbed inspector video editor, clip/color timeline.
  • nodes + MetaSound — js/MetaSoundEditor/ and engine/soundes/ host the audio graph editor.

window.SMViewportSystemengine/SMViewportSystem.jsMulti-viewport panels.
window.historyManagerhistory/history.jsUnified undo/redo.
window.persistenceManagerprocessing/persistence/ScenePersistenceManager.jsScene save/load/auto-save.
window.cameraSystemindex.jsCamera rig manager.
Scene patching To keep the hierarchy, timeline, LOD system and persistence in sync, SM Engine pathtches scene.add()/scene.remove() at boot so every object added or removed is automatically registered with the timeline (unless flagged userData.ignoreInTimeline) and the auto-saver.
